# Comic Production Kit — working rules

This is the **US English edition** of the author-owned Japanese kit. Read `docs/localization/TRANSLATION-POLICY.md` and `docs/localization/UPDATE-WORKFLOW.md` when maintaining it. US English defaults override the Japanese edition's language, lettering, and reading-order defaults. Keep upstream identifiers and provenance stable.

- Do not use `chrome:control-chrome`. Do not launch, connect to, or control Google Chrome or Microsoft Edge, including through Playwright, Selenium, CDP, headless execution, or commands that open the default browser. Inspect images with image tools and research through web search/retrieval without browser control. Give the user a path or URL when HTML needs viewing. See the browser prohibition in `docs/knowledge/codex-operation.md`.
- With an active NovelAI Opus subscription, default to one image per request and no more than 28 steps (V5 starts at 23; V4.5 and earlier at 28). Follow the shared page-dimension policy for the selected tool, and fit frames and final PNGs to the actual generated dimensions. Before execution, check all settings, selected dimensions, V5 limits, and additional reference charges. Do not consume Anlas without explicit paid-use authorization. See the Opus section in `docs/knowledge/ai-production.md`; do not apply these conditions to all generators.
- The basic workflow accepts characters, a synopsis, and a page count and produces comic PNGs for web publication using defaults. Put preferences in the project `OPTION.md` and print-only settings in `PRINT-OPTION.md`. Do not require answers to every additional setting before starting.
- Use panel templates by default. When existing templates cannot express the intended direction, use a custom layout and record the page, intent, and reason. Follow explicit user requirements to require or avoid templates. For imagegen, actually supply a numbered layout reference image and panel content before page generation; default to generating the whole page. See `docs/knowledge/panel-layout-policy.md`. Do not impose that generation method on NovelAI or other tools.
- With imagegen, generate lettering and balloons in the image by default; with other tools, add them after drawing. Choose based on the drawing tool before artwork starts rather than requiring a typesetting answer during scaffolding. See “Finishing text and balloons” in `docs/knowledge/page-layout.md`.
- Explain dimensions as width × height and distinguish requested/actual generation dimensions, frame-placement dimensions, and final PNG dimensions. By default, fit the frames and export to the actual full-page generation size, scaling margins and strokes together. The bundled 2000×3000 frame assets do not prescribe generation or output dimensions.
- Default to left-to-right panel and balloon order, then top to bottom. English dialogue and monologue use horizontal, word-wrapped lettering, usually centered inside speech balloons; captions may be left aligned. Use ordinary English punctuation. Do not apply the Japanese edition's no-period rule or 20-character comma threshold. See `docs/knowledge/japanese-manga-readability.md` (a compatibility filename). Do not mirror artwork to change reading order.
- Optional Japanese polishing skills are disabled by default and apply only to Japanese source text, not English prose. In a project that selects one, initialize it on first use. Git is assumed installed; ask before installing it if missing. For a skill requiring Gemini, obtain explicit permission to transmit text and consume quota before installation, even if the environment is available. Selecting the option alone is not permission. See `docs/knowledge/optional-skills.md`. Do not distribute downloaded skills or consent receipts in the kit or new projects.
- This directory maintains and distributes the kit. Normally do not produce a comic at this root or below it, including `templates/manga-project/`. For a production request, run `scripts/New-MangaProject.ps1` (on Linux, `scripts/New-MangaProject.sh`) to create a project outside the kit, by default `../ProjectName/`. Resume an existing work in its own folder. Kit documentation/code maintenance and distribution tests under `.work/` belong here.
- The kit primarily targets Codex. Use `-AgentMode Claude` only when the user explicitly chooses Claude (including Claude Code); this adds `CLAUDE.md` and `AGENT-MODE.md`. In that case, say Claude instead of Codex in completion guidance. Otherwise use Codex mode.
- When the user explicitly chooses Gemini (Antigravity), use `-AgentMode Antigravity` in PowerShell or `--agent-mode Antigravity` in Bash. Add `GEMINI.md` and its dedicated `AGENT-MODE.md`, and tell the user to reopen Antigravity. Do not treat Gemini CLI or other environments as Antigravity. Do not distribute these files to default Codex projects.
- Confirm successful creation and the destination's existence. Give the full absolute path both as a clickable Markdown link and as copyable text. Say “Reopen Codex in this folder,” and add “If you need help, tell me your environment (Windows or Mac; app or VS Code), and I will explain the steps.” Do not research or repeat reopening instructions on every creation. If asked for steps, consult current official information appropriate to the environment, explain it in English, and cite URLs and the verification date. See `docs/knowledge/codex-operation.md`. Creation does not switch this conversation's working directory; begin planning, storyboarding, thumbnails, and artwork from a session opened in the project folder.
- Only when the user explicitly insists on producing a comic inside the kit, explain the exception procedure. The user must personally create the ordinary file `特別な理由でこのフォルダの中で漫画を作ります.txt` in the kit root (the Japanese filename is retained for compatibility). Verify it exists before production. Do not create, copy, or run a generation command for it on the user's behalf, and never distribute it in the template. Its existence alone is not a production request; silence is not confirmation. See the exception in `README.md`.
- When asked what the folder can do, start with creating and reopening an individual project, then explain its capabilities using the README workflow and `docs/knowledge/manga/08-workflow-review.md`. Center comic planning, text storyboards, and thumbnails; film/video is an optional aid.
- Present PNG previews, apply requested changes, and present them again until the user confirms no further changes. If PSD creation has not been requested, ask and wait; if already requested, do not ask again, and create, verify, and deliver it after PNG approval. Silence is not approval. See `docs/knowledge/psd-handoff.md`.
- A human normally finishes the work in CLIP STUDIO PAINT and publishes it. Create CBZ files or video prototypes only on explicit request.
- Use US English for explanations, guidance, fields, handoff notes, and layer names. Preserve product names, source URLs, paths, machine identifiers, and original license texts. Communicate with this edition's owner in Japanese when maintaining the localization; use the Japanese owner questionnaire for unresolved preferences.
- Use relative paths in documents, configuration, and saved records. Display an existence-checked absolute path in the temporary message guiding the user to reopen a project. Do not hardcode the repository folder name. Distinguish external URLs, internal tool path resolution, temporary user-facing display, and persistent records.
- Shared knowledge and operations belong in `docs/knowledge/`; character, information, and acting guidance in `docs/knowledge/manga/`. Consolidate readability and general review knowledge in the relevant documents directly under knowledge. `docs/knowledge/review-workflow.md` maps sources to skills. Scene supervision belongs in `docs/knowledge/supervision/`; version 0.3.2 introduced the existing gag material plus 15 experimental themes. Read only necessary themes and distinguish source claims, production proposals, and unverified effects. Skills live in `skills/`, project masters in `templates/manga-project/`; `docs/knowledge/supervision/distribution.json` limits distributed supervision files. See `docs/architecture.md`.
- On resume, read local `docs/PROGRESS.md` and `docs/PLAN.md`; create them if needed and update them at milestones. These local records, `backup/`, `.work/`, artwork, and generated production outputs are excluded from publication. Public English-maintenance records are separately curated under `docs/localization/`.
- Retain source URLs, access dates, and scope, and distinguish verified facts, production proposals, and unverified matters. For older references with an unknown access date, label 2026-09-12 as the date the record was supplemented, not the access date.
- Record project feedback only when asked to retain it. Do not ask whether to record it, maintain unsolicited feedback candidates, or send unsolicited changes upstream. Keep ordinary progress, revision, and verification records as needed.
- Save mandatory process requirements in the project `config/process-requirements.json` only when an experienced user requests registration. Use `manga-process-checker` to discuss the instruction level, conditions, checkpoints, completion criteria, and carry-forward scope. For delegated decisions, decide and record the reason. Do not return personal rules to this kit/common templates or use a global user store. Use `New-MangaProject.ps1 -ProcessRequirementsFrom` only for an explicitly named source project. Do not transfer execution records, hook settings, or trust settings. See `docs/knowledge/process-checker.md`.
- The main agent integrates production decisions; skills provide role-specific procedures. Keep credentials, project assets, and unsorted logs out of common templates.
- Do not rerun publication tests or automated checks after every edit. For a user-requested pre-commit check, propose the relevant scope using the changes and previous results, and obtain authorization before running it unless already authorized for this scope and reruns. A check request alone, silence, or consent to a different scope is not that authorization. Ask with reasons before expanding the scope. Ordinary content/diff reading remains appropriate, and unrun tests must not be reported as passing. See `docs/publication.md`.
- Publication uses direct Git commits from this checkout; do not create a release ZIP or separate release directory. Follow `docs/publication.md` for publication-scope, candidate, and staged-diff checks. `examples/` holds user-designated public examples: remove Exif, text, and generation metadata from PNG/JPEG files before publication, and do not copy examples into new projects. Commit, publish, or transmit externally only within the requested scope.
