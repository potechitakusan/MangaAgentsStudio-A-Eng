# Comic image production and PSD handoff

This skill is bundled with the manga project. Paths are relative to the working project root. When testing originals in the distribution kit, use `templates/manga-project/config/review-profiles.json` for emphasis settings.

Confirm target scene, intent, and input (synopsis / text storyboard / rough storyboard / manuscript / reference art). Read effective emphasis under `docs/knowledge/review-workflow.md`. The primary perspective is `characterConsistency`; consult relevant sections of `docs/knowledge/ai-production.md` for judgments.

If the selected method supplies images as conditions to Qwen, NovelAI, or another tool and generates individual panels, use bundled `manga-external-panel-i2i` and `docs/knowledge/external-panel-i2i.md`. Consult model-specific documents for inputs/symptoms and service documents for connection/pricing. Do not force this branch for connection-only checks, text-only generation, or new imagegen panels/pages. Distinguish Qwen-Image 2.1 production records from Qwen-Image-Edit-2511 references.

Before generating page artwork, read `docs/knowledge/panel-layout-policy.md`; record adopted template IDs or custom staging and reasons per page. Use templates as a rule, prioritizing user requirements or disabling. For imagegen, actually supply a numbered layout image and panel contents in image input/instructions, defaulting to whole-page generation. Custom layouts also need references; record reasons for separate-panel generation when needed. Do not universally prohibit frames/balloons/text in generated images; compare with plan/source text afterward and correct stray numbers and mismatches. Character-reference-only generation does not need page layouts. Follow environment-specific workflows for NovelAI and other tools.

For NovelAI, read the Opus section of `docs/knowledge/ai-production.md`. With Opus default to no Anlas consumption and check dimensions, steps, sample count, extras, and V5 allowance. Apply adopted dimensions in `config/page-layout.json` and the generation tool; fit frames/final PNG to actual generation under `docs/knowledge/page-layout.md`. Never make test generation requests with unverified 0 Anlas; paid use stays within existing explicit authorization. Call the subscription, Anlas, and V5 allowance check API on the first generation and roughly once every 10 generations thereafter (the script counts automatically to avoid excessive API calls; it checks on every run if conditions change, the previous run did not complete, or remaining V5 allowance is low). Paid-use authorization and cost-confirmation flags remain unchanged. For panel assets, follow `docs/knowledge/novelai-composed-production.md`: generate one character trial before production, compare appearance, and generate near the panel aspect ratio. Generate beyond panel bounds and show the needed area with topmost frames/masks. Do not over-enlarge and lose the storyboard subject, action, or framing. Follow that document's request-prompt construction and fix `generate` warnings before sending. Once page PNG previews are typeset with NovelAI, build and present the page-flipping HTML viewer according to "Page-flipping HTML viewer for PNG previews" in `docs/knowledge/novelai-composed-production.md` (do not launch a browser). Save one JSON per panel in `input/novelai/requests/`, and as a rule assemble requests for NovelAI API generation with `scripts/novelai_compose.py` (V5 default; V4.5 only when specified by the user). When modifications are needed for additional features such as i2i or references, modify and use this script as the base (pass sending and cost checks through `novelai_batch.py` and `novelai_api.py`). Use `scripts/novelai_batch.py` for generation, adoption, and rebuilding, and record human-repeatable commands in `docs/production/NOVELAI-BATCH.md`. Character, style, and background prompts become `.env.novelai` variables only on human request and after confirming names and contents. For introduction and editing, see the variable section of `docs/knowledge/novelai-composed-production.md`; for user-facing change examples, see `docs/novelai-prompts/README.md`.

When using PixAI, read `docs/knowledge/pixai-api.md` and `docs/knowledge/pixai-composed-production.md`. Because credit balance cannot be queried via the API, send only generations whose scope the user has explicitly authorized. Do not make the user look up model version IDs. When a model is specified by name or characteristics, first choose from `config/pixai-models.json` (`python -X utf8 scripts/pixai_models.py list`; 15 official models) and pass `--model <name>`. For a model not in the list, ask only for the model-page URL, register it in the project list with `scripts/pixai_models.py add <name> --url <URL>`, and inform the user of the displayed terms of use (commercial use and online sharing). Ask the user to copy the URL after clicking the version tab only if the page cannot be read. Before using a LoRA, record its base model and terms of use in the project once with `scripts/pixai_models.py lora --url <URL>`. Because PixAI has no per-character inputs or position pins, write multiple characters with explicit subjects and positional relationships in a single prompt (`pixai_compose.py --layout`). Follow "Constructing request prompts" and "Pre-send content verification" in that document when creating and checking requests.

### Choosing PixAI features

| Situation | Tool to use | Key points |
| --- | --- | --- |
| New panel | `scripts/pixai_compose.py` → `pixai_batch.py generate` | For panels with 2+ characters or regenerations, use `batchSize` 4 and choose from 4 candidates (e.g., 4,000 credits for 1 image vs. 7,000 credits for 4 images on Tsubaki.3 pro 1k). Use 1 image for the first run of a simple single-character panel |
| Only part of the panel is wrong (ears, props, hands, erasing a halo) | `scripts/pixai_edit.py inpaint <ID> --add "<subject + fix>" --ellipse …` | First choice. Inherits the original request's settings and creates the mask. Keep the mask small and off the face. Adding elements succeeds in roughly 2 out of 4 images, so generate 4. Tsubaki.2 images are automatically repaired with Tsubaki.3 |
| Change overall mood or season | `scripts/pixai_edit.py i2i <ID> --add "…" --strength 0.6` | 0.6 makes small changes while keeping composition; 0.9 makes large changes |
| Copy composition from a rough or existing image | `pixai_compose.py --model haruka2 --controlnet canny:<image>` | Use `canny` or `depth` on an SDXL model. `openpose` does not work on ordinary illustrations |
| Distinguish left and right characters | `--layout` → if it misses, use inpainting | `latentCouple` separated characters in testing but increased the headcount, so do not make it the default |
| Character consistency | Use the exact same appearance phrase in every request (turn into `.env.pixai` variables if requested) | LoRA effectiveness is unverified; test with a character trial if used. IP-Adapter is accepted by the API, but passing two characters blended them |

Because i2i, inpainting, ControlNet, `latentCouple`, and IP-Adapter are undocumented in the official reference, add `--allow-unverified` only when the user consents to using them (acceptance and behavior were verified on 2026-10-25, but may change without notice). The style preset `flat-anime-pastel` tends to produce a halo above the head (a motif reminiscent of existing IP). Always compare the redrawn area side by side with the original image at full resolution before adopting a result. When asked about model or style-preset looks, provide the absolute path to the kit's `resources/pixai-model-samples/index.html`.

### NovelAI prompt construction and pre-send verification

Only when creating, revising, or checking requests for NovelAI, always read "Expanding scene relationships and continuing state into each request" and "Pre-send content verification" in `docs/knowledge/novelai-composed-production.md`. Expand relationships and continuing state into the actual requests and verify them; dialogue, lettering, and balloons are typeset afterward. For work that uses only imagegen, do not load this detailed document or the NovelAI verification record, and do not apply this section's method.

When specifying the on-screen position of characters or objects in NovelAI, read "Position pins (Character Positions)" in the same document. Use per-character input and position pins in the panels that need them, consistent with the prompt order, left/right wording, and post-typesetting crop. For the `use_coords` and `centers` format in the API, see "Position-pin requests" in `docs/knowledge/novelai-api.md`. Do not make them mandatory in every panel, and do not apply them to generation or editing outside NovelAI.

Follow "Text, balloons, and finishing" in `docs/knowledge/page-layout.md`: imagegen normally generates text/balloons in the image; other methods add them afterward. Decide from the tool before artwork; a typesetting answer is not a startup prerequisite. English lettering defaults to horizontal, centered balloon text, natural punctuation, and left-to-right/top-to-bottom reading.

After drawing, actually open images and complete the per-panel "Post-artwork comparison" in `docs/reviews/NAME-REVIEW.md`. Before separate typesetting finish that comparison, then fill "Post-typesetting checks" with `scripts/typeset_manga.py` results and artwork-containing review images. For imagegen with text/balloons, inspect the completed page after generation. Follow `docs/knowledge/japanese-manga-readability.md` for lettering, balloons, and in-world text; do not add unrequested titles/page numbers.

Confirm fixed character features, references, desired changes, and available environment. Consider ComfyUI for repeated comparisons and available editing tools for local changes. If ComfyUI brings NovelAI output toward a style, record conditions preserving original features. Verify named models exist and are compatible; never treat uninstalled models as installed. Fixed seeds alone do not guarantee character consistency. Record conditions, trial counts, failures, and results using `docs/experiments/TEMPLATE.md`; if nothing was generated, mark unproven. Never write key values in replies or logs. Check applicable installed skills before image generation/editing and do not execute nonexistent tools/APIs.

Results include location, observation, hypothesized reader effect, severity, improvement, and effects lost. Consultation gives proposals and selection reasons. Reviews honestly report no issue or inability to judge. The main agent integrates acceptance and records it in `docs/reviews/`. Save reusable feedback in `docs/feedback/` only when requested; otherwise do not ask whether to save it.

For requests to finish a comic, read `docs/knowledge/manga/08-workflow-review.md` and `docs/knowledge/psd-handoff.md`. First make, inspect, and present PNG previews from production assets. Apply/present revisions and obtain confirmation that the latest PNG needs no further changes. Without a PSD instruction, ask and wait; do not create it yet. "No PNG revisions" and silence are not PSD instructions. If PSD creation was already instructed, do not ask again; after PNG confirmation create, validate, and hand off.

Preserve separable art, text, and balloon elements before PSD creation, and approved dialogue in `docs/production/DIALOGUE.md`. Record the reviewed PNG/version/answer and PSD request status in `docs/production/PSD-HANDOFF.md` and progress. Reopen requested PSDs, inspect layers, compare recomposition with confirmed PNGs, and read all pages through. Record specifications, unknowns, merged elements, and remaining human finishing before handoff. Awaiting PNG confirmation or PSD answers is legitimate. PNG-only, consultation-only, and partial-generation requests finish at their requested scope.

Normally a human finishes in CLIP STUDIO PAINT before publication. CBZ requires explicit request. A PSD text layer does not imply editable CLIP STUDIO PAINT text. If actual import cannot be checked, mark it unverified. Explanations and layer names use English.
