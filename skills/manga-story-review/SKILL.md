# Comic story review

This skill is bundled with the manga project. Paths below are relative to the working project root. When testing the original in the distribution kit, use `templates/manga-project/config/review-profiles.json` for emphasis settings.

Confirm the target scene, intent, and input (synopsis / text storyboard / rough storyboard / manuscript / reference art), then read effective emphasis under `docs/knowledge/review-workflow.md`. The primary perspective is `story`. For judgments, consult relevant sections of `docs/knowledge/story-structure.md`.

Check who wants what, what prevents it, and which choice changes the situation. Use basic format 1 as a design aid whose roles may overlap or be omitted. Select among the five patterns as hypotheses for connecting scenes; do not confidently attribute them if their originator is uncertain. Distinguish beneficiary from object of pursuit. Where events are merely listed, propose cause-and-effect connections. Matching a structure does not guarantee an engaging story.

Include the location, observation, hypothesized reader effect, severity, proposed improvement, and effect that would be lost. For consultation, give proposals and reasons for choosing them. In reviews, honestly record "no issue" or "cannot judge" when appropriate. The main agent integrates final decisions and saves them in `docs/reviews/`. Record reusable feedback in `docs/feedback/` only when the user asks to retain it; otherwise do not ask whether to record it.

For story, characters, setups/payoffs, and endings, consult `docs/knowledge/manga/05-story-character.md`; for acting and language, `docs/knowledge/manga/04-scene-dialogue-props.md`; for serialization, ensembles, and comedy, `docs/knowledge/manga/06-series-comedy.md`, as needed. Do not convert film acts or ratios into fixed comic page counts. Consult `manga-supervision` for humorous scene proposals; the main agent decides compatibility with the central story effect.
