# manga-terminology-review

This skill is bundled with the manga project. Paths below are relative to the working project root. When testing the original in the distribution kit, use `templates/manga-project/config/review-profiles.json` for emphasis settings.

Confirm the target scene, intent, and input (synopsis / text storyboard / rough storyboard / manuscript / reference art), then read effective emphasis under `docs/knowledge/review-workflow.md`. The primary perspective is `terminology`. For judgments, consult relevant sections of `docs/knowledge/glossary.md`.

Confirm this request is a review. Compare only relevant terms in the project `docs/story/TERMS.md` and shared glossary. Identify locations with different meanings for the same term, inconsistent names for the same setting, or inadequate first-use explanations. Do not accidentally standardize away voice, nicknames, or intentional foreshadowing. For changes, state preferred wording, reasons, and exceptions; distinguish story-specific definitions from shared terms when adding terminology.

Include the location, observation, hypothesized reader effect, severity, proposed improvement, and effect that would be lost. For consultation, give proposals and reasons for choosing them. In reviews, honestly record "no issue" or "cannot judge" when appropriate. The main agent integrates final decisions and saves them in `docs/reviews/`. Record reusable feedback in `docs/feedback/` only when the user asks to retain it; otherwise do not ask whether to record it.
