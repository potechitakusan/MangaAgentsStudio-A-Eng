# Manga project working rules

- Do not use `chrome:control-chrome`. Codex must not launch, connect to, or control Google Chrome or Microsoft Edge.
- At startup and on resumption, check `config/process-requirements.json`. If active requirements exist, follow `.agents/skills/manga-process-checker/SKILL.md` and compare evidence when reporting milestones such as completed text storyboards or pages, and before handoff. Check a "strong instruction" before starting its specified stage as well. Zero requirements need no detailed checking or reporting. Do not treat missing or invalid data as zero requirements. Preserve existing mandatory conditions.
- When a user with production experience asks to make a step mandatory, use that skill to discuss and register content, "instruction / strong instruction" level, conditions, checkpoints, completion criteria, and carryover to the next work in detail. For delegated decisions, Codex chooses details and records reasons. Do not add requirements automatically from feedback without a registration request or send personal instructions back to the distribution kit. See `docs/knowledge/process-checker.md` for storage, carryover, and Hooks.
- With an active NovelAI Opus subscription, default to one image per request and at most 28 steps (initial value 23 for V5, 28 for V4.5 and earlier). Follow shared page settings appropriate to the tool; fit frames and final PNGs to actual generated dimensions. Before execution check all settings, including chosen dimensions, V5 allowance, and extra charges for references and other features. Do not consume Anlas without explicit authorization for paid use. Details and sources: the Opus section in `docs/knowledge/ai-production.md`. Do not impose these rules on other generation environments.
- For NovelAI projects, read `docs/knowledge/novelai-composed-production.md` and `config/novelai-production-policy.json`. Codex handles panels and typesetting; NovelAI generates assets without text or frames.
- When creating, revising, or checking NovelAI prompts before sending, use "NovelAI prompt construction and pre-send verification" in `.agents/skills/manga-ai-production/SKILL.md`. Expand the scene's relationships and the state carried over from the previous panel into each request, then verify the body text, per-character text, coordinates, and negative text that will actually be sent. Never send dialogue text, `Text:`, or positive instructions for lettering or balloons to NovelAI; typeset them afterward. Do not treat the absence of automatic warnings as completed content verification.
- Save a separate request JSON for each NovelAI panel, including character trials, in `input/novelai/requests/` (filename format `p01-03.json`). Use `generate`, `adopt`, and `build` in `scripts/novelai_batch.py`; do not replace them with custom generation/composition scripts. Keep per-page commands and adoption records in `docs/production/NOVELAI-BATCH.md` so humans can retry a page or all pages, choose images, and continue. Follow the request JSON, batch generation, and prompt-construction sections of `docs/knowledge/novelai-composed-production.md`. Describe the storyboard in visible terms: no negative terms in positive prompts; visible posture/expression instead of intent; a state instead of an action in progress; identify whose body appears in close-ups; separate two characters or put posture and position first; repeat each character's identifying features in identical words in every request. After selecting a character trial, register features and the cast per request in `input/novelai/characters.json`. Fix `generate` dry-run warnings before sending; to retain warnings, record reasons before adding `--accept-warnings`.
- Put character, style, and background prompts in `.env` variables (`NOVELAI_CHAR_…`, `NOVELAI_STYLE_…`, `NOVELAI_BACKGROUND_…`) and reference them as `${VARIABLE_NAME}` in request JSON only when a human asks. Confirm names and values before using `novelai_batch.py env-set` and `templatize`. Do not display or modify other `.env` settings, including API keys. For the human-facing editing and regeneration steps, see `docs/novelai-prompts/README.md`.
- Preserve `input/pages/page-NN.json` and `input/typeset/page-NN.json` so humans can rebuild PNGs and PSDs with identical page, panel, and within-panel placement using `novelai_batch.py build --page N` (add `--write-psd` for PSD). Generate assets beyond panel bounds; hide unused areas with topmost frames and masks. Human-run PSD output is intended for later painting-software adjustments.
- Use `scripts/novelai_api.py` and `docs/knowledge/novelai-api.md` for API connections. `key-status` checks key loading; `status` checks subscriptions without generation. Never display secret-file contents in conversation or logs. After reviewing the request, generation requires `--execute` and cost confirmation for this run. Do not set unverified confirmation flags or treat generation alone as permission for paid use. After timeouts/failures, inspect execution records and never automatically resend an unknown result.
- If NovelAI needs a key, show `.secrets/novelai.env` with `NOVELAI_API_KEY=YOUR_ACTUAL_TOKEN`; explain that the left side is a public setting name and the right side is secret. Never ask the user to paste the actual token in conversation or reenter an already configured key. Guide connection setup without requiring a detailed diagnostic prompt from the user. Distinguish configuration, authentication, and connection failures; connection failures alone do not justify key changes. Explain possible restrictions and follow the environment's permission procedure.
- If a NovelAI style is unspecified, wait for the user's style ID before drawing. When style is missing or style/sample guidance is requested, only verify the kit's `resources/novelai-style-samples/index.html` exists and supply its absolute path. Resolve the kit from `project.json`'s `sourceKitRelativePath`, relative to the project root. If unknown, moved, or missing, report it as unverified and clarify its location. Do not copy sample images into the project.
- Legacy Japanese polishing is disabled by default in this English edition and applies only to explicitly requested Japanese source text; it is not an English polishing feature. Follow `docs/knowledge/optional-skills.md` for selection, installation, resumption checks, and disabling. Ask before installing missing Git required to fetch a selected skill. Before installing a Gemini-based skill, always confirm permission to transmit text and consume Gemini quota, even when the environment is available. Enabling OPTION alone is not permission. Pass `-GeminiConsent Granted` plus the actual answer and scope only after an explicit answer. With silence or refusal, do not fetch, install, or make test calls; continue normal production.
- Apply polishing only with the selected skill and to specified targets.
- A basic request supplies characters, synopsis, and page count. Produce Web page comics through PNG without extra configuration. Fill unspecified details with defaults and production judgment; do not require all OPTION or print answers before starting. Format/basic frame: `docs/knowledge/page-layout.md`. Read `PRINT-OPTION.md` only when printing is selected.
- Use panel templates as a rule and select IDs before artwork generation. If templates cannot adequately express intended staging, Codex may design that page's layout. Record page, intent, and reason in `docs/production/PANEL-LAYOUT-POLICY.md`; do not ask for approval for every exception. Details: `docs/knowledge/panel-layout-policy.md`.
- With imagegen, decide layout and reading order before generation, with or without templates. Actually supply a numbered layout image and each panel's contents; an ID/path string does not attach a reference image. Default to whole-page generation; use individual panels when needed. Frames, balloons, and text may be included, but compare placement, content, and dialogue to the plan and remove explanatory numbers/guides afterward. Follow tool-specific workflows for NovelAI and other environments.
- Distinguish "requested/actual generation dimensions → frame layout → final PNG," expressed as width × height. Default to fitting frames and final PNG to the actual full-page generation. Scale margins and strokes from reference values on resizing. The bundled 2000 × 3000 px frame reference is not a generation/export requirement.
- With imagegen, default to text/balloons generated in the image; with other tools, add them after drawing. Decide from the tool before drawing; do not require a typesetting answer to start. For separate imagegen lettering or imagegen used only for references/local corrections, follow "Text, balloons, and finishing" in `docs/knowledge/page-layout.md`.
- After drawing, actually open images and complete the per-panel "Post-artwork comparison" in `docs/reviews/NAME-REVIEW.md` (plan, observed image, match, acceptance). Before separate typesetting finish that comparison; then record `scripts/typeset_manga.py` results and visual review of images containing artwork in "Post-typesetting checks." For imagegen text/balloons, inspect the completed page after generation. Give speech balloons tails; draw text on in-world objects as part of those objects. Do not add unrequested titles/page numbers. See `docs/knowledge/japanese-manga-readability.md` (compatibility filename; English comic guidance).
- Voice examples in briefs/character settings are speech-style samples, not ready-made dialogue. Only text explicitly designated fixed source wording is used verbatim (D10, `docs/knowledge/manga/04-scene-dialogue-props.md`).
- Check time transitions, image density, and action continuity in rough storyboards and PNGs. Keep adopted lettering in `docs/production/DIALOGUE.md`, reusable correction conditions in `docs/reviews/NAME-REVIEW.md`, and check applicability on later pages. Optional stylistic polishing applies only to OPTION-selected targets.
- This work project was created by `New-MangaProject.ps1` or `New-MangaProject.sh`. Confirm the working folder is its root using `project.json`, then produce here. Do not return to the distribution kit to draw or create another replacement project. No in-kit exception file is needed. When reading this as an original template, follow the distribution kit's `AGENTS.md` to create a separate project.
- Present PNG previews, apply/present revisions, and obtain the user's confirmation that no revisions remain. Without a PSD instruction, ask and wait before creating one. With an existing PSD instruction, do not ask again: after PNG confirmation, create, validate, and hand off. Silence means neither "no revisions" nor permission to create. Requested PSD completion requirements: `docs/knowledge/psd-handoff.md`. Normally humans finish in CLIP STUDIO PAINT before external publication. CBZ requires explicit request.
- Explanations, know-how, fields, handoffs, and layer names use US English. Preserve product names, source URLs, paths, and machine identifiers.
- One project produces one comic. Story settings go in `docs/story/`; decisions, sources, and progress go in `docs/`.
- On resumption read `docs/PROGRESS.md` and `docs/PLAN.md`. Update current status/next actions at startup, decision changes, generation/validation, and interruptions.
- At startup read `OPTION.md`; missing files/items use `docs/knowledge/project-options.md` defaults. Prioritize user instructions and explain effective settings once, including panel-template proportions. Record adopted values, sources, file presence, and SHA-256 in progress.
- On resumption and before each stage check OPTION changes. For changes after startup, clarify intent and defer application to affected work until answered. Do not re-ask about conversationally authorized changes. Follow `docs/knowledge/project-options.md` for missing files, deletions, and pending confirmation; reflect adopted settings in this file's default policy. Read detailed references only as needed.
- Shared operations/knowledge: `docs/knowledge/`; character, information, and acting: `docs/knowledge/manga/`; readability/shared review: corresponding knowledge-root documents. Consolidate material with the same purpose. Reference-to-skill map: `docs/knowledge/review-workflow.md`. Supervision: `docs/knowledge/supervision/`. Read only relevant perspectives and use corresponding `.agents/skills/` in consultation/review. Follow 1–5 emphasis and scene overrides in `config/review-profiles.json`.
- For scenes needing an included supervision effect, consult `.agents/skills/manga-supervision/SKILL.md` during text-storyboard drafting and consider improvements after actually viewing PNGs. Route through `docs/knowledge/supervision/routing.md`. The 15 version-0.3.2 additions are experimental. The main agent specifies central effect/emotion to preserve and integrates decisions. Without dedicated knowledge use general knowledge/review. Separate verified facts, proposals, and unverified points; image-unseen reviews are preliminary.
- The main agent integrates production policy and review decisions. Use skills as procedures and delegate to subagents as needed with target, purpose, and emphasis.
- Use `.agents/skills/manga-video-previsualization/SKILL.md` only on an explicit request to test cinematic staging in video. Ordinary comic production does not insert video generation. Record conditions, speed, and adoption in project docs.
- Default dialogue/monologue is horizontal US English; panels and balloons read left to right, then top to bottom. Honor adopted direction exceptions and record reasons. Text on objects follows context. Prioritize reading order and emotional effect.
- Center dialogue lines within balloons with inner padding. Wrap English at word boundaries and preserve natural punctuation/contractions. Use periods, commas, questions, and exclamations according to meaning; Japanese character-count punctuation restrictions do not apply. Record deliberate alignment exceptions. Check storyboards, approved text, polished text, and PNGs consistently; see `docs/knowledge/japanese-manga-readability.md`.
- Use `docs/knowledge/glossary.md` only during review; review story terminology in `docs/story/TERMS.md`.
- Record feedback in `docs/feedback/` only when asked to retain it. Otherwise do not ask about recording, maintain upstream candidates, or report "no new findings." Keep necessary ordinary progress, decisions, generation conditions, and validation. See `docs/knowledge/feedback-workflow.md`.
- API keys belong in project `.secrets/` or local environment variables, never docs, shared templates, image metadata, or feedback.
- For `wait_agent`, explicitly use an in-range `timeout_ms` twice the estimated remaining time; if unknown, state the default. This rule itself does not request delegation.
- Start with `docs/MANGA-KNOWHOW.md`. Focus on comic planning, text/rough storyboards; consult film, television, or `screenwriting-skills` only when useful. Film storyboards are not a routine stage.
- Record PNG review targets/answers, PSD request status, specifications/validation, dialogue source, and remaining human finishing in `docs/production/PSD-HANDOFF.md` and `docs/production/DIALOGUE.md`. Awaiting PNG confirmation or a PSD answer is a legitimate stage. Requested PSDs are unfinished until creation, validation, and handoff. A completion request does not automatically include PSD, CBZ, or external publication.
